## 识别的5个新合理化

### 新合理化 #1: 工具复杂度逃避

**合理化**：
```
"知识图谱命令太复杂，我更熟悉grep"
```

**违反场景**：
- 时间压力 + token限制
- 用户请求："GraphQL 400错误"
- 代理心理：/kg:query看起来比grep复杂

**现实**：
- /kg:query语法：`/kg:query "关键词"`
- grep语法：`grep -r "关键词" docs/`
- 知识图谱：一次查询完整（问题、解决方案、代码、文档）
- grep：需多次尝试不同关键词

**根本原因**：
- 对知识图谱命令的恐惧（怕复杂）
- 对grep的熟悉（习惯路径）
- 低估了知识图谱的完整性

**反措施**：
1. 在技能中强调知识图谱命令的简单性
2. 对比：一次完整查询 vs 多次grep尝试
3. 性能数据：240倍速度改进

---

### 新合理化 #2: 性能恐惧

**合理化**：
```
"知识图谱更新太慢，我先用grep"
```

**违反场景**：
- 用户紧急请求（"5分钟内给我代码示例"）
- 代理心理：更新知识图谱需要时间，先grep快速给出答案

**现实**：
- 增量更新：<5秒
- 全面检测：<30秒
- grep查找：2-3分钟
- **跳过知识图谱更新 = 数据过时 = 返工**

**根本原因**：
- 误解了知识图谱的更新性能
- 低估了grep的时间成本
- 高估了"快速答案"的价值

**反措施**：
1. 明确性能数据（增量<5s，全面<30s）
2. 强调跳过更新的代价（数据过时）
3. 对比：grep 2-3分钟 vs 知识图谱 <500ms

---

### 新合理化 #3: 局部思维谬误

**合理化**：
```
"只改了一个文档，不用更新知识图谱"
```

**违反场景**：
- 文档修改后执行update-docs
- 代理心理：单个文档变更影响有限，不需要更新图谱

**现实**：
- 单个文档变更可能影响多个关联：
  - 文档引用边（引用/被引用）
  - 文档相似度边（与相关文档的相似度）
  - 概念关联边（涉及的技术概念）
  - 解决方案验证边（相关的测试验证）

**根本原因**：
- 局部思维（只看直接变更）
- 缺乏系统性思维（未考虑关联影响）
- 低估了增量更新的自动化程度

**反措施**：
1. 强调混合更新策略（自动检测关联）
2. 说明增量更新的自动关联处理
3. 提供案例：单个文档变更的连锁反应

---

### 新合理化 #4: 简化思维陷阱

**合理化**：
```
"这个问题很简单，不需要查知识图谱"
```

**违反场景**：
- 用户问题看似简单（"GraphQL 400错误怎么办？"）
- 代理心理：简单问题 = 简单答案 = 不需要复杂工具

**现实**：
- **简单问题往往有深层关联**：
  - GraphQL 400错误 → 枚举格式 → TypeScript迁移 → React 18+兼容性
  - 表面：枚举值错误
  - 深层：前后端类型系统不一致

- **知识图谱揭示隐藏关系**：
  - `/kg:query "GraphQL 400"` → 找到问题、解决方案、代码、文档、测试
  - `/kg:related solution:graphql-enum-fix` → 发现相关经验（类型同步、测试验证）

**根本原因**：
- 简化思维（低估问题复杂性）
- 线性思维（问题→解决方案，忽略了关联）
- 过度自信（认为自己知道所有相关信息）

**反措施**：
1. 强调"简单问题 ≠ 简单关联"
2. 提供案例：GraphQL 400的深层关联
3. 说明图谱的价值：揭示隐藏关系

---

### 新合理化 #5: 工具限制误解

**合理化**：
```
"知识图谱太大了，我只查相关部分"
```

**违反场景**：
- 用户请求："React Hooks相关的所有文档"
- 代理心理：图谱太大，手动限定范围更高效

**现实**：
- **知识图谱支持过滤和范围查询**：
  - `/kg:query --type document "React"` （只查文档节点）
  - `/kg:query --archived false "React"` （排除归档）
  - `/kg:related doc:react-best --depth 1` （1跳范围）

- **手动限定范围的代价**：
  - 遗漏跨类型关联（文档 ↔ 解决方案 ↔ 代码）
  - 遗漏深层关联（2跳、3跳）
  - 增加认知负担（需要记住所有过滤条件）

**根本原因**：
- 误解了工具能力（不知道图谱支持过滤）
- 低估了手动限定的代价（遗漏关联）
- 过度自信（认为自己能准确限定范围）

**反措施**：
1. 强调图谱的过滤和范围查询能力
2. 对比：手动限定 vs 工具过滤
3. 说明深层关联的价值（2跳、3跳发现）
