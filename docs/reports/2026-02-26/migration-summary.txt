================================================================================
                          标准迁移步骤
================================================================================

阶段1: 检查依赖 (5分钟)
  ├─ 检查 Entity 是否存在 (backend/models/entities.py)
  ├─ 检查 Service 是否存在 (backend/services/*/)
  └─ 检查 Repository 是否存在 (backend/models/repositories/)

阶段2: 创建缺失组件 (30-60分钟)
  ├─ 创建 Entity (继承 BaseModel,添加验证器)
  ├─ 创建 Service (继承 BaseService,实现业务逻辑)
  └─ 创建/修改 Repository (返回 Entity 而非字典)

阶段3: 迁移API层 (1-3小时)
  ├─ 替换 fetch 函数为 Service 调用
  ├─ 替换手动验证为 Entity 验证
  ├─ 替换字典返回为 Entity.model_dump()
  └─ 更新异常处理 (捕获 ValidationError)

阶段4: 测试验证 (30分钟)
  ├─ 运行单元测试 (pytest)
  ├─ 运行API契约测试
  └─ 手动测试API端点

================================================================================
                          迁移检查清单
================================================================================

API层检查:
  □ 所有端点使用 Service (而非 Repository/fetch)
  □ 所有输入使用 Entity 验证 (而非 validate_json_request)
  □ 所有输出使用 model_dump() 序列化
  □ 所有异常使用 ValidationError 捕获

Service层检查:
  □ 继承 BaseService (统一缓存管理)
  □ 返回 Entity 对象 (而非字典)
  □ 使用 @cached 装饰器 (而非 lru_cache)
  □ 调用 self.invalidate_*() 清理缓存

Repository层检查:
  □ 继承 GenericRepository
  □ 返回 Entity 对象 (而非字典)
  □ 使用 fetch_one/fetch_all_as_dict
  □ 启用缓存 (enable_cache=True)

Entity层检查:
  □ 继承 BaseModel (Pydantic)
  □ 使用 Field 定义字段
  □ 使用 field_validator 验证
  □ 实现 XSS 防护 (html.escape)

================================================================================
                          关键风险提示
================================================================================

🔴 高风险:

  1. 缓存不一致 - 迁移后需 FLUSHALL
  2. API兼容性 - 使用 Field(alias=...) 保持兼容
  3. 性能回退 - 使用 model_dump(mode='json') 优化

🟡 中风险:

  4. 测试覆盖不足 - 迁移前补充测试
  5. 业务逻辑遗漏 - 仔细对比代码

🟢 低风险:

  6. 类型注解不完整 - 使用 mypy 检查
